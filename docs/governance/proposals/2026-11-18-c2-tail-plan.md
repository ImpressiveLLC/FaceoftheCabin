Before an implementation PR starts, Cowork names its author, approves its bounded scope and references the merged C1-S1 baseline. Each PR must:

1. Pin the immutable before commit, fixture/document hashes, harness version, role and 6000-character budget; report the same cases against the candidate commit. Keep baseline outputs unchanged. The source snapshot above is not the C1-S1 measurement freeze.
2. Prove the reported gap on the baseline and complete delivery of the intended `path#section` after the fix, using exact content equality. Category agreement alone is not delivery. Record first category, selected set, omitted sections and total document characters separately. A missing source section fails the check; it is not counted as a successful abstention.
3. Preserve the 120 routing pins, all current authored slice cases, existing negative tests, mirrored fixture bytes and unrelated category content. Compare the existing 150 phrasings and disclose any movement. Do not change a pin or an expected answer just to make the fix pass.
4. Add password, token and secret variants where the new wording can match; complete `configuration.md#credentials-and-access` must remain delivered. Test combined phrases and overlapping spans, not only one alias at a time. Increasing a boost or adding overlapping phrases requires evidence that unrelated guidance is not displaced.
5. Check administrator, adult household, child, kiosk, service and null audiences against the existing section policy. Zero administrator-section leaks. Grafana's household section keeps its existing household eligibility; it is not made administrator-only to simplify the test.
6. Report all results as spent development evidence, never held-out acceptance or answer quality. No model is needed. Any runtime-facing routing change still needs exact-head independent review, CI, the named merge owner's deploy decision and read-only live verification; a healthy deployment is not evidence of answer quality.

Each group is a separate implementation PR after its scope is approved. No accumulated alias bundle, blanket boost increase or global matcher rewrite is proposed. Stop and return a design choice if the intended text cannot coexist with required credential/setup guidance in the existing budget.
