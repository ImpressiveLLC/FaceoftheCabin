## Consistent failure patterns

The dominant failure is corpus access and retrieval: the live service searches only device KnowledgeNodes by word overlap, so operating/configuration/governance questions usually return unrelated device nodes or no context. Sources are often genuine records but do not support the answer, failing the citation rule. The model then produces an ungrounded “I don't know” or a short hallucinated instruction.

Three higher-risk patterns need priority in the first enhancement: identity renaming (Q04), workflow/safety interpretation (Q08), and independent-installation inputs (Q18). Q11 did not leak a raw credential, but it also did not demonstrate the role-specific pointer contract. Q23's refusal is safer than following the hostile premise, but it still does not establish reliable contradiction or injection handling.

## Recommendation and ratification trigger

Do not claim C1/C3 completion. The result supports the already-ratified corpus-first sequence: add a document-aware, audience/version/provenance-aware context path, then re-run this same frozen Q01–Q25 set with paired current-service and improved-context trials. Keep vector retrieval conditional on measured context size and retrieval failures. The first implementation PR should preserve the existing response contract, add precise document/section citations, fail closed on unsupported operational claims, and include regression tests for Q04, Q08, Q11, Q18 and Q23.
