## Bottom line
1. Public sets cannot be graded against OUR corpus. Their questions point at their documents. What transfers: question shapes, an unanswerable taxonomy, generation and judge prompts that run on any knowledge base, grader calibration, and known failure modes of small models.
2. "Validated elsewhere" is real but narrow: it validates the method and the graders on THEIR corpora (often GPT-4 labels), not our answer keys.
3. Public sets may be in model pretraining data. Whether llama3.2:3b saw any of them is unknown (possible, not established), so they must not be the sealed acceptance set. Use them for a development set, grader calibration and templates.
4. The sealed 120-question acceptance set still needs a blind author. Public material cuts the custodian's work (taxonomy, templates) but does not replace blind authorship and a domain verifier.

## Provider terms note (The owner asked 23:08 CST, whether competitors will share outputs)
Hosted-model outputs are governed by each provider's terms. Anthropic's commercial terms (D.4) bar using the service to build a competing product or train competing models (author's reading; no dated primary retrieval is recorded here, so verify the current terms before any provider is selected). A trade report (RuntimeWire, Aug 18, 2026; secondary, xAI page not loaded) says xAI's acceptable use policy bars helping rivals directly or indirectly. Before any hosted-model generation, check the generator's license. Prefer open-licensed generators and sources. ## How the metadata is recorded
One row per derived item in a provenance sidecar (JSON lines) so the source and context travel with every question: source_id, source_url, commit_or_version, retrieved_date, license and license_status (verified or unverified), terms_notes, redistribution (yes, no, unknown), transformation (template only, rewritten, synthesized by tool X with model Y), local_item_id, intended_use (template, dev, calibration), contamination_risk (possible or unknown for public sets; exposure of our model is not established), consumed (true once used for tuning).

## Proposed use, layers
1. Template bank and taxonomy (no custodian needed): map our 72/24/24 split onto UAEval4RAG's six unanswerable categories for the 24 probes and onto ragas query types for answerable and partial. Record the mapping.
2. Development set (open, spent by design; proposed, needs separate approval before any run): run S1 and S2 generators over our corpus, then a human or independent reviewer checks each item against the cited source. This is the fast-feedback set. Never reported as acceptance. Needs a generator model swap for S1 (no OpenAI key in our stack); a generator that sees the corpus is fine here because this set is not sealed.
3. Grader calibration (proposed, needs separate approval before any run): run rubric r2 and the two blind graders on a small labeled slice of S4 manual subsets and S5 to measure grader agreement. Reference labels: general S4 labels are GPT-4 annotations, with only limited human-validation subsets (arXiv 2407.11005v2 section 3.4 and appendix 7.6). Unless an exact human-labeled subset is identified, report the result as agreement with synthetic labels, not human gold. Requires the data to be reachable from a host with HF access (the Cowork container shell likely cannot; the PC or Code session can).
4. Sealed acceptance set (120): unchanged. Blind custodian plus domain verifier, hash-locked, aggregate-only disclosure, built with the taxonomy above. Public items never enter it.
