Against the plan's acceptance line ("critical failures not higher than r9-b; intent not lower"), E1 and E2 both meet it on the totals. Neither meets any package gate (intent at least 0.90, slot F1 at least 0.90, zero critical failures). The totals hide churn, so the per-fixture view matters:

- **E1** fixed `gold-07` and `gold-38` and broke `gold-48` (a `set_device_state` row that became `express_need`). The ledger flags `gold-48` as a regression.
- **E2** fixed `gold-13`, `gold-14` and `gold-38`, and broke `gold-02`, `gold-16` and `gold-43`. The ledger flags two of them (`gold-16`, `gold-43`) as new critical failures, which the ledger says to review before iterating. Confusions moved from "clarify read as a command" toward "command read as clarify", plus one `express_need` read as `clarify`.
- **Slot F1** moved up in both (E1 +0.048, E2 +0.130 against today's base), but it is a small-denominator metric (about 50 expected slot pairs).

## Cautions

1. **The base reproduction is not bit-identical to r9-b.** Same prompt, schema, gold, tag and temperature 0 gave the same 8 failed fixtures and the same intent and critical counts, but slot F1 is 0.569 today against 0.581 on 2026-10-21 (tp 35, fp 38, fn 15). That is a difference between two runs of one input, so about 0.01 of F1 is run-to-run noise on this host (see item 2 for the two later base runs). The ledger's "PROMPT UNCHANGED" warning on that pair is expected: it is a rerun. Candidates are compared with today's base, not with the October figure.
2. **Repeats (added later the same day, at Nate's word).** Base, E1 and E2 each ran three times (rounds `-rep2` and `-rep3` are the repeats; the first run has no suffix). In every condition the set of failed fixtures was identical in all three runs, so the intent and critical-failure results repeat exactly and the regressions above (`gold-48` for E1; `gold-02`, `gold-16`, `gold-43` for E2) are real, not run noise. Slot F1 was identical in all three runs for E1 (0.617) and E2 (0.699); only the base varied (0.569, 0.569, 0.581). Report sha256 (first 8) of the repeats, kept on the M920q: base `ae55b2a1` and `5b2459ae`, E1 `82994c20` and `fb9290d6`, E2 `b75a7618` and `7c49b0c0`. Checking those fixtures by hand is still open.
3. **E1 is a restructure, not an addition.** The r9-b prompt already had an ordered check list and a short list of invented contrast examples. E1 reorders it (questions before commands, one short clarification naming only what is missing, garbled input asks to repeat) and merges two checks. It adds no schema or vocabulary change.
4. **E2 examples come from reviewed synthesis templates.** `synthesis-templates.json` is project-authored, outside the gold and outside the held-out split; none of its texts equals a gold text and no template id is in a gold group. One example per intent, first utterance of each: `train-help`, `train-clarify-pronoun-1`, `train-need-cold`, `train-status`, `train-poc2-once`, `train-clarify-nounit-pair-1`, `train-light-kitchen-on`, `train-secret`. The sealed sets (safety 80, authored test 170, the 30 reserved OHF rows) are not on this machine and were not read. Provenance: project-authored, no outside text.
5. **A gold text already sits in the baseline prompt.** The baseline `system.txt` quotes "I am cold" (gold-23) as an example of an expressed need. This predates the round and is in all three prompts, so it does not change the comparison, but the gold is not fully clean of the prompt.
6. **Latency.** Median per-request time 5.2 s for base and E1, 3.4 s for E2; no transport errors in any round. Wall time 6 min 54 s, 6 min 49 s and 4 min 45 s. Peak memory was not sampled.
