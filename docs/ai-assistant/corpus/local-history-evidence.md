## Corrections promoted into the corpus

The source review also recovered two specific runbooks already in [MAINTENANCE.md](../../MAINTENANCE.md): stale edge-cached `host-config.js` can silently break shared data sync, and Frigate's substitution namespace differs from Compose's environment interpolation. These support Q02/Q12 and Q13/Q15 respectively. No new operational procedure has to be invented to explain them.

One further correction comes from checking the guide against code: Family Hub `sendNote()` saves a failed send locally, while `refreshNotesFromServer()` replaces the cached list with the server response. There is no replay queue in that path. The guide's suggestion that reconnecting eventually shares the local note is therefore not a reliable recovery instruction. Preserve the text before signing in, refreshing or changing configuration; check for an existing server copy before deliberately resending. This discrepancy is now explicit in [Q02](eval-answer-evidence.md#q02--recover-a-note-visible-on-only-one-device).

No recovered source demonstrates a complete independent clean-host installation and recovery trial for the selected current platform. Existing POCs and historical incident fixes remain useful evidence for their individual components. Q20 is an execution trial, so its honest answer is an executable acceptance scope with a NOT RUN result, rather than a missing-document question or a reason to stop corpus work.
