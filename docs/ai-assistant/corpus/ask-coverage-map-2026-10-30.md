# Ask corpus coverage map: rules, workflows, alerts, devices, presence, maintenance

Read-only analysis for W-117 (corpus answers first, Nate 2026-10-26). Checked against `origin/main` at `868dee2` (2026-10-30). No corpus edit, no GitHub write, no live call. Sealed or held-out evaluation files were not opened.

## Facts: the corpus boundary

What `POST /api/helpdesk/ask` can put in front of the model, verified in code:

1. **Entry point.** `TinyHelpdeskController.ask` passes the question and the caller's `HouseholdRole` to `TinyHelpdeskService.ask(question, role)` (`cabin-orchestration-platform/backend/src/main/java/com/cabin/orchestrator/helpdesk/TinyHelpdeskService.java`).
2. **Path 1, keyword categories (the only way documentation reaches Ask).** `AskContextBuilder.buildContext` loads `classpath:rag/context-fixtures-r2.json` (`backend/src/main/resources/rag/context-fixtures-r2.json`, byte-identical to `docs/ai-assistant/rag/context-fixtures-r2.json`). It has 27 categories. Each keyword matches only as a whole word or phrase with an optional `s`/`es` plural. The highest summed score wins, and ties go to declaration order. No keyword match means no category. The map is compiled into the jar, so a map change needs a backend deploy. Section text is read live from the mounted docs.
3. **Which documents can be read at all.** `ReviewedDocumentSource.ALLOWED_PREFIXES = ["ai-assistant/user-guide/"]` and `ALLOWED_FILES = ["ai-assistant/contributing.md"]`. A section reaches Ask only if a category lists it, by GitHub-style anchor. A level-3 heading counts as part of its mapped level-2 parent. All categories share a 6000-character budget (`ask.context.max-document-chars`).
4. **Audience gate.** A document entry with no `audience` defaults to administrator. A non-administrator, or a caller with no role, gets only `household` entries. The household entries are: operations.md `users-and-family-data`, `capability-map`, `what-the-presence-badge-means`, `arming`, `who-counts-...-d24`, `what-is-not-settled`; ask-and-helpdesk.md's three behavior sections; contributing.md's two sections; and four environmental-nodes.md sections. **Every rules, workflow, device, maintenance and configuration section is administrator-only.**
5. **KB nodes inside categories.** A category can also name `knowledge_node` rows (`platform.*`, `system.*`, `family_hub.*`). The `AskContextBuilder` javadoc and the map's own description say the database holds none of these, and a missing ref is skipped with a WARN log. If a category ends up with no context (for example a household caller on an admin-only category whose nodes are absent), the service falls back to Path 3.
6. **Path 3, word overlap.** When there is no category or no context, `retrieveRelevant` scores every `knowledge_node` row by shared words (stopwords removed, words of 3 or more characters) and keeps the top 5. Those rows are:
   - `KbGeneratorService` output: DESCRIPTION ("<name> is a <maker> <model> (<type>) located in <area>.") and RELATIONSHIP ("<name> reports: <fields>.") for each in-scope device, regenerated daily at 03:00.
   - Two seeded CREDENTIAL_POINTER rows (`Blink Cloud Account`, `Resend`) from `CredentialPointerSeeder`. `CredentialPointerRedactor` hides their content from anyone who is not an administrator.
   - Any SETUP, TROUBLESHOOTING or CREDENTIAL_POINTER row a person added through `POST /api/kb/curate`.
   No documentation is ever retrieved by word overlap.
7. **Refusal and fallback.** No facts produces "I don't have any information about that yet." If Ollama fails, the raw facts are concatenated and returned with `answeredByModel:false`. The prompt says to answer only from the facts and to cite `[source: ...]` labels.
8. **Not in the corpus**, even though the material exists on main. These would answer many of the questions below, but Ask never reads them:
   - `docs/ai-assistant/knowledge/heater-control.md` and `frigate-detection.md`: human-worded Q&A. The heater file says itself that it is not supplied to Ask.
   - `docs/USER_GUIDE.md` (alerts, notifications, sign-in)
   - `docs/MAINTENANCE.md`, `docs/STORAGE_ARCHITECTURE.md`, `docs/NOTIFICATION_PATH.md`, `docs/PRODUCT_NOTES.md`, `docs/REPLICATION.md`
   - `docs/ontology.yaml` (served at `/api/ontology/entities`, not used by Ask)
   - `docs/ai-assistant/corpus/*` (eval oracles, deliberately excluded)
   - `CLAUDE.md`
9. **Allowlisted but unmapped sections.** These are readable by `ReviewedDocumentSource` but no category lists them, so they never reach Ask:
   - maintenance.md `a-camera-is-not-delivering-frames`, `a-zigbee-plug-or-sensor-is-listed-twice-...-w-88-2026-10-21`, `new-hardware-pending-install-2026-10-16`, `close-the-incident`
   - operations.md `products-and-responsibility`
   - configuration.md `explicit-source-disagreement`, `new-device-classes-not-yet-configurable-2026-10-16`, `remaining-configuration-work`
   - ask-and-helpdesk.md `d28-naming-...`, `add-or-correct-knowledge`
   - independent-installation.md `establish-the-actual-installation-plan`, `acceptance-record`, `link-targets`
   - contributing.md `doc-27-environmental-content`, `future-in-app-workflow`
10. **Keyword vocabulary gaps.** No keyword in any of the 27 categories contains: `alert`, `notification`, `notify` (only the id `notify_critical`), `snooze`, `ignore`, `silence`, `pair`, `add`, `remove`, `delete`, `disk`, `trim`, `link`, `invite`, `guest`, `demo`, `arm`/`armed` (only `disarm`), `heater`, `water`, `leak`, `camera`, `frigate`, `node-red`, `grafana`, `home assistant`, `offline`, `room`, `schedule`, `undo`, `reset`, `fire`, `history`, `alarm`, `banner`, `status check`, or plain `zigbee`/`device`/`devices`. The plural rule also misses other inflections: "deployed", "renaming", "paired" and "armed" do not match `deploy`, `rename`, `pair` or `arm`.
11. **Routing simulation.** An offline replica of `AskContextBuilder.select()` (see NOT_RUN) was run over the 150 plain-language phrasings in the table below:
    - **95 of 150 (63%) select no category**, so they get word overlap over device descriptions only.
    - 24 route to `rules_workflows`, which is admin-only.
    - By my reading, at least 15 of the 55 routed phrasings land on a category whose sections do not answer them. Examples: "Why didn't I get a push notification?" goes to `deployment_source`; "Why is my plug listed twice?" goes to `opportunity_status`; "Will my password rotate automatically?" goes to `credential_redaction` instead of the rotation section; "How long is sensor history kept?" goes to `live_sensors`.

Status key:
- **COVERED**: a clear passage answers the question in human words.
- **PARTIAL**: an answer exists but is incomplete or needs several sources.
- **JARGON**: the answer exists only in internal terms (ids, API paths, enum names).
- **MISSING**: no passage in the boundary.
- **STALE/WRONG**: a corpus passage contradicts code or decisions on main.

"Reach" is a separate question: whether the human phrasings actually route to that passage. Possible values: yes; partial; no (keyword miss); no (unmapped); misroute (wrong category). "Admin" means the passage reaches an ADMINISTRATOR only.

## Top 15 gaps (ranked by how likely a household member or admin is to ask, times how wrong the answer would be)

1. **Alert silencing is invisible to Ask (A3 to A7).** Ignore for now, Remind me in, the silenced list and Restore, the 1-hour-only critical floor, and Open device have no passage, and no category has an `alert` keyword. These are the most common Rules & Alerts actions. The silence-a-leak case (A5) is safety-relevant.
2. **Phone notifications (A8).** There is no corpus answer, "push" misroutes to deployment, and the only human text (`USER_GUIDE.md`, out of boundary) says critical alerts reach the phone. The 2026-10-12 record says the backend push is dead while the ntfy topic is blank. Mapping USER_GUIDE as-is would give a confidently wrong safety answer.
3. **Location roles (D6, D7) are stale.** The corpus says the backend does not know roles and that maintenance visits are not recorded. Main now counts primary users only, records `MAINTENANCE_VISIT`, and has Config > Location Roles with "Counted but not assigned". Merged on 2026-10-30; whether it is deployed is not verified.
4. **Reset and "undo" (B7).** People will ask how to undo a workflow. The truth is that there is no undo, and Reset or Mark seen never reverses an action or reopens the valve. The corpus says only "a person can clear any execution".
5. **Leak response and turning the water back on (A11).** Human wording ("water", "leak") routes nowhere. The corpus is keyed to `valve` and `action_main_water_valve_open`, and the reviewed procedure is absent (G06).
6. **Optimization Opportunities (A12) is stale.** K19 says only `POWER_DRAW_ANOMALY` exists, but code and UI also ship "Duplicate readings". The right text is in the unmapped W-88 section, and the routed K19 section is the wrong one.
7. **Lifecycle words (C4, C5).** "Use this device", "Not now", "Saved for later" and Available versus Assigned are unexplained. The corpus uses CANDIDATE and ASSIGNED, so "Saved for later" (DEFERRED) appears nowhere.
8. **Remove and restore a device (C7).** Only "Remove applies IGNORE" in admin text. Nothing says that data is kept, that Home Assistant and Zigbee pairing are untouched, or how to bring a device back (Review previously exposed).
9. **Adding devices (C1, C2, C3).** Pair a Zigbee device, Scan for devices, Register manually and Import have no steps. "pair", "add" and "import" are not keywords.
10. **Storage warnings and Trim old backups (E1, E2).** These are missing, and the human answer lives only in `STORAGE_ARCHITECTURE.md`. The disk reached 99% on 2026-10-13, so this will be asked.
11. **Device on/off and On the Way preheat (C14, C18).** Missing in the boundary, while a ready Q&A sits in `docs/ai-assistant/knowledge/heater-control.md` outside the allowlist. It contains a Tailscale IP and entity ids, so it needs review before mapping. Meanwhile word overlap on "heater" returns only the heater's device description, which invites an invented answer.
12. **Guest Access, demo links and Managed Users (E6, E7).** These are missing, and an admin would ask them often (adjuster or contractor access, revoking a link).
13. **Schedules (B14).** No passage says that no time-based trigger exists, so the model may invent one.
14. **Status Checks overview, severity levels and tab dots (A1, A2, A10).** No passage names the main card. The current UI label "Status Checks" appears nowhere in the corpus.
15. **Correct but unreachable W-88, camera and Zigbee text (C9, C17, E11, E12).** Human-worded maintenance answers exist in allowlisted files but are unmapped, and the phrasings misroute. Mapping them is the cheapest win.

Structural, applies to all rows: every rules, workflow, device and maintenance section is administrator-only, so a household member gets no documentation for any A, B, C or E question. The keyword router misses 63% of the plain phrasings.
